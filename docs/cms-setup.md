# Редакция блога и медиа

Адрес: `/admin/`. Это Pages Functions + отдельная D1 база + R2 bucket, без внешней CMS и без секретов в клиентском коде. До подключения bindings существующий сайт работает как раньше; вход сообщает, что хранилище не подключено.

## Запуск в Cloudflare

Сначала подключить на preview `feature/block-cms` проекта `vetratoria`, проверить полный цикл, затем включить на production. Production и preview должны использовать **разные** базы и bucket. Не использовать `CONTACT_DB` и не менять настройки формы заявок.

1. Создать D1 `vetratoria-cms-preview` и R2 `vetratoria-cms-preview` (после проверки — отдельные production ресурсы).
2. Pages → нужный проект → Settings → Bindings → Preview: D1 binding `CMS_DB`, R2 binding `CMS_MEDIA`. Для production аналогично, с production ресурсами.
3. Применить SQL к нужной базе:

```sh
npx wrangler d1 execute vetratoria-cms-preview --remote --file=server/cms/schema.sql
npm run cms:import
npx wrangler d1 execute vetratoria-cms-preview --remote --file=server/cms/seed.sql
```

Импорт добавляет 9 статей, 14 альбомов, 369 существующих медиа. Он идемпотентный: повторный запуск не заменяет тексты из админки. Существующие `.php` и `/ru/blog/` адреса сохранены. Старые изображения остаются статическими; новые файлы идут в R2.

4. Создать секреты локально: передать выбранный начальный пароль через переменную окружения `CMS_INITIAL_PASSWORD`, запустить `npm run cms:secrets`. Скрипт создаёт исключённый из Git `.dev.vars.cms` с правами 0600, не печатает значения. Не отправлять этот файл в репозиторий или чат.
5. Pages → Settings → Variables and Secrets: добавить как **encrypted secrets** `CMS_ADMIN_PASSWORD_HASH`, `CMS_AUTH_SECRET` из файла; `CMS_ADMIN_USERNAME` — выбранный логин. Значение по умолчанию для логина — `админ`. Сам пароль в Cloudflare не хранится, только PBKDF2 hash. Bootstrap создаёт владельца только при первом успешном обращении к login; смена пароля через админку не отменяется redeploy.
6. Повторно развернуть ветку после настройки bindings/secrets. Открыть `/admin/`, войти и выполнить проверки ниже.

Публикация сразу записывается в D1 и выводится через SSR, без сборки сайта и GitHub-токенов. Сессия HttpOnly Secure SameSite=Strict на 12 часов. Изменения требуют same-origin запроса; вход ограничен восемью попытками за 15 минут на IP.

## Проверка перед включением production

- Войти, открыть импортированную статью и убедиться, что текст и фото на месте.
- Создать тестовый материал, загрузить фото, добавить текст/фото+текст/галерею, поменять порядок, скрыть блок.
- Обновить страницу после сохранения — черновик должен остаться.
- Проверить предпросмотр телефона и компьютера. Опубликовать и открыть материал в другом браузере без входа. Проверить фильтры блога и sitemap.
- Изменить опубликованный текст: до повторной публикации на сайте должна оставаться предыдущая версия.
- Открыть один материал в двух окнах: второе сохранение старой версии должно сообщить конфликт и сохранить текст в открытом редакторе.
- Проверить историю, восстановить прошлый текст в черновик. Снять тестовый материал с публикации: URL должен вернуть 404, карточка исчезнуть.
- Загрузить и открыть MP4, проверить перемотку (R2 range requests).
- Создать редактора: ему доступны черновики и медиа, публикация и управление доступом закрыты.
- После переноса на production проверить старые ссылки статей. Не привязывать preview к production D1/R2.

## Локальная проверка

Node 24 (для встроенного SQLite) и Python 3 (разовый импорт HTML):

```sh
npm run build
npm run check
npm run cms:import
npm run cms:test
node --test scripts/tests/contact.test.mjs
node scripts/cms/dev.mjs
```

Для `dev.mjs` нужен `.dev.vars.cms`. Локальная база и загрузки находятся в `.cache/cms`; сервер доступен только на `http://127.0.0.1:4174/admin/`. Использует тот же API, но упрощённую публичную оболочку без Cloudflare HTMLRewriter. Это не замена проверке Pages preview.

## Работа редактора

Шаблоны: статья, фоторепортаж, короткая новость, видео. Блоки: текст с простым форматированием, фото, фото+текст слева/справа, две фотографии, галерея сеткой/лентой, видео, цитата, FAQ, кнопка. Фотографии при загрузке уменьшаются до 2400 px и переводятся в WebP; видео MP4/WebM — до 25 МБ. Внешнее видео — YouTube. Alt и подпись задаются отдельно. Обложка, страна, спорт, дата, язык и SEO-поля доступны в редакторе.

Автосохранение — серверное с контролем версии; неподтверждённые правки не выдаются за сохранённые. При закрытии окна с несохранённым текстом браузер предупреждает. Доступна история последних 100 версий; все версии хранятся в базе. Файлы, используемые даже в старой версии, удалить нельзя. При длительной работе потребуется политика очистки истории/неиспользуемых файлов.

## Ограничения первой версии

- Нет отложенной публикации, переводов/связки RU↔EN, обрезки фото и видеотранскодирования. Поле языка хранит метку материала; переводы пока отдельные публикации.
- Списки показывают до 1000 материалов и 2000 файлов; пагинация потребуется при росте.
- Карточки на главных страницах направлений пока остаются из статической сборки. Блог, его страницы по странам, медиаразделы и sitemap читают CMS.
- Публикации защищены входом и ролями; сами медиа публичны по URL. Не загружать закрытые документы.
- До подключения D1/R2 и проверки Cloudflare preview нельзя считать production CMS запущенной.

## Откат

Вернуть прежний commit сайта — статические страницы останутся. Сначала сохранить D1 export и R2 файлы: после отката новые CMS статьи не будут выводиться, пока эта версия CMS не возвращена. Не удалять D1/R2 при откате.
